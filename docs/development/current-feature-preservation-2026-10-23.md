# 定制业务保留清单、必要依赖与切换门槛

日期：2026-10-23。当前 fork 源码基线：`8de9d81614d68d680324973e5398f4da85a255bc`；原版比对基线为 `upstream/v0.2.17`。本清单是 [企业 AI 网关建设方案](standalone-platform-architecture-2026-10-23.md) 的范围与验收依据。

**完整保留当前项目的定制业务；sub2api 原版功能仅在与定制业务存在具体依赖时纳入。** 分阶段只调整定制业务及必要依赖的交付顺序。原版的其他功能由原版 sub2api 自身提供，不作为新平台重建、兼容或切换的要求。

本清单保留 **130 个定制业务条目**，另列必要依赖与工程检查。条目按模块与验收面划分，跨模块可能覆盖同一能力，不表示 130 个独立产品功能。条目沿用 D／B／A／C 编号，便于追踪；工程项沿用 E 编号。此前 221 项属于全仓能力盘点，其中原版功能不能据此自动成为迁移任务。全部目标实现仍待实施与联调，本轮是范围设计和源码静态核对。

## 原版功能如何纳入必要依赖

原版依赖必须写出「哪个定制条目使用它、使用哪些字段／操作、缺失会破坏什么行为、由平台还是渠道承接」。仅因为原版有接口、菜单或配置，不构成纳入理由。功能可用本地等价实现解耦，不要求保留原版表结构或整套模块。

## 实现归属与切换门槛

每项定制业务及适用依赖建立简单验收记录：旧入口／角色、新模块／入口、使用的依赖切片、数据与配置、正常与异常用例、历史核对、结果与证据。状态按「待实现 → 待迁移／联调 → 待验收 → 已通过」推进；源码存在或渠道有接口不能替代业务验收。

**定制业务整体切换条件是 130 项定制条目、已列明的必要依赖和已启用网关能力通过验收，并完成冻结基线后的定制增量核对。** 原版无关功能不属于这道门槛。MVP 用于内部或受控试点；按企业／角色分批迁移时，只核对该批次的定制流程及其完整依赖，不要求复制整个 sub2api。

保留定制业务的历史身份、金额、文件、配置开关和失败恢复；不迁移无关原版表。退出本次范围不授权删除旧系统数据或停用原版业务。切换时按对象和业务归属划定写入与计量责任，防止双发模型请求或重复扣款。

企业与上游用户解耦：每个企业—渠道绑定一份活动上游凭据；员工与报告使用平台凭据。sub2api 必需的技术 Key 持有人仅留在 Adapter 配置。平台账号与供应商订阅账号的本地可见关系，是 C 系列定制授权，不是企业关联上游计费用户。

- BI v1 Connector、导入事实复制、AnalysisContext、收藏笔记、报告外链分享及原独立 Worker 已退役。[backend/migrations/257_bi_independent_users.sql:1](../../backend/migrations/257_bi_independent_users.sql#L1) 明确移除旧开发表并重建独立身份；[docs/mobile-bi/implementation.md:3](../../docs/mobile-bi/implementation.md#L3) 与当前路由一致。迁移保留现存 Desktop 原始会话/用量/报告版本、新 BI 身份与授权、隐私配置和审计；若存在旧导出或备份，应登记为历史档案，不恢复成运行接口。不能承诺仓库已经删除的 v1 表仍有当前数据库数据。
- BI 采用率、留存、部门/岗位统计、企业应用/业务场景、知识复用、质量评估与受控分享等在 BI 返回 `unsupported/not_connected`（[backend/internal/bi/desktop_http.go:101](../../backend/internal/bi/desktop_http.go#L101)）；组织模块有部门/岗位，不等于 BI 已接通统计。保留现有「未接入」状态即可，不能把演示数据当真实已实现能力，也不能把其他模块已实现组织能力删掉。
