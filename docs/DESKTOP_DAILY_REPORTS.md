# 企业对话归集与管理总结

平台管理员在企业配置中启用「归集总结」并填写分析模型。开启前须启用对话上报。关联用户只读查看；关闭开关后隐藏「日报与总结」Tab，历史内容仍保存在服务端，管理员可查看。

每天北京时间 02:00 后处理前日数据。例如 10 月 10 日执行的任务，读取 `stopped_at` 位于北京时间 10 月 9 日 00:00 至 10 月 10 日 00:00（不含结束时间）的对话。个人日报和企业总结都标记为 10 月 9 日。

「个人日报（归集）」与「企业总结」独立展示，共用日期选择，默认显示企业总结。个人列表包含当前全部未删除成员及目标日期有记录的历史成员；无记录成员显示「当日无对话记录」，不创建日报，不参与失败统计或覆盖率分母。企业整日无对话时跳过全部 AI 调用，不创建报表。

任务执行前及每次 AI 调用前，检查企业、承载用户、开关、模型配置、分组模型和路由限制、可调度账号以及计费资格。预检不发送收费探测请求，也不占用用户 RPM 计数；实际调用沿用正常 Gateway 的限流、并发控制、账号切换和计费。分析请求使用企业系统托管 Key，凭据不提供给客户端，也不能通过外部 Gateway 请求使用。分析用量纳入企业总用量，单独展示所选日期范围的分析消耗，不进入成员排行。

首次开启从启用当天的数据开始，次日生成。后台只自动创建前一日报表任务；已创建任务在模型恢复或服务重启后继续处理原日期。生成期间分析模型或承载配置发生变更时，原任务暂停，由管理员重新生成，保证两阶段使用同一份配置。历史日期及停机期间未创建的任务可由管理员按日期补跑。

## 手动操作

| 操作 | 行为 |
|---|---|
| 按日期补跑 | 为已有对话且尚未生成的历史日期创建任务；已有成功结果不重复生成 |
| 失败重试 | 保留成功个人日报及已成功的分批结果，重试失败项，随后更新企业总结 |
| 重新生成 | 重新读取该日期对话，包含迟到记录，使用当前模型与承载配置生成；保留原内容直到对应新报表成功 |

对话内容只是分析数据，内置 Prompt 不执行其中的指令。日报区分用户描述、AI 建议和已有证据支持的完成情况，并保留来源引用。缺失 Response 或截断内容会随输入保留。超长输入分批归集，再合并生成最终日报；企业总结同样支持分批合并。

每个失败分批调用最多自动尝试 3 次，重试间隔为 1 分钟、5 分钟。临时不可用属于待执行状态，不消耗调用失败重试次数。部分成员失败时，根据成功日报生成总结并展示缺失成员和覆盖情况；没有任何成功日报时不生成总结。关闭开关停止后续调用，已经发出的请求仍可能完成并产生正常用量。

## API

管理员接口前缀为 `/api/v1/admin/desktop/organizations/{organization_id}/daily-reports`，关联用户只读前缀为 `/api/v1/desktop/organization/daily-reports`。

- `GET /?date=YYYY-MM-DD`：个人日报列表与任务元信息，默认日期为北京时间前一日。
- `GET /{date}/members`：全部成员日报与无记录状态。
- `GET /{date}/members/{member_id}`：成员日报详情和来源记录 ID。
- `GET /{date}/summary`：独立查询企业总结、覆盖情况和缺失成员。
- 管理员 `POST /{date}/run`：提交 `{"mode":"generate"}`、`{"mode":"retry"}` 或 `{"mode":"regenerate"}`。日期必须早于北京时间今天；有数据返回 `202`，无对话返回 `200` 且不创建任务，条件不满足返回 `422`，任务正在执行返回 `409`。

关联用户身份从当前登录用户解析，不能指定其他企业。报表请求使用 `Cache-Control: no-store`。原始对话查询继续受现有上报开关和企业边界限制。接口完整定义见 [Desktop OpenAPI](DESKTOP_API_V1.openapi.yaml)。

## 模型执行记录

个人日报详情和企业总结分别展示执行记录，记录每次请求传入 Gateway 的 Model ID 快照、开始和结束时间、状态、生成批次、合并轮次、分批编号和尝试次数。每次分批分析、合并、重试及重新生成均产生独立记录；模型配置变更或重新生成不会覆盖旧记录。

调用前必须先持久化执行记录；记录无法保存时暂停 AI 调用。条件检查后未实际执行的尝试标记为「条件不满足，未执行」。进程中断且未确认结果的记录保留为「执行中 / 结果未确认」，不将其推断为成功。执行记录不包含对话正文或 API Key，继承报表的企业隔离与开关访问规则。
