# 渠道对账 SOP

本文规定每月从渠道平台导出报表、导入系统、处理异常和月末核对的做法，适用于 SUNRATE 账户 `72778936`。系统的入账规则见[渠道账单导入](channel-import.md)，字段格式见[标准账单模板](statement-template.md)。

## 1. 节奏与分工

| 时间 | 做什么 | 谁 |
| --- | --- | --- |
| 每月 1–5 日 | 导出上月报表，导入系统，处理异常，完成月末核对 | 财务 |
| 入金或购汇后 3 个工作日内 | 上传入金凭证 | 财务 |
| 发现导错批次 | 撤销批次，重新导出导入 | 管理员（只有管理员能撤销） |
| 月末核对完成后 | 复核核对清单 | 管理员 |

月中也可以随时导入，例如刚入金或刚充值卡余额后。重复导入不会重复记账。

## 2. 导出报表

### 2.1 清单

每次对账导出以下报表，**区间一致**：

| # | 报表 | 导出时选择 | 格式 | 是否必需 |
| --- | --- | --- | --- | --- |
| 1 | 收付款余额对账单 Statement of Payment Balance | Currency 选 **HKD** | PDF | 必需 |
| 2 | 收付款余额对账单 Statement of Payment Balance | Currency 选 **USD** | PDF | 必需 |
| 3 | 卡余额流水 CARD_BALANCES | — | xlsx | 必需 |
| 4 | 授权明细 AUTHORISATIONS | — | xlsx | 必需 |
| 5 | 入金记录 Record_Collection | — | xlsx | 区间内有入金时必需 |
| 6 | 购汇记录 Record_Currency_Conversion | — | xlsx | 区间内有购汇时必需 |

手续费明细 `SUNRATE_FEES_*.xlsx` 不需要导出。收付款余额以后出现其他币种时，每个币种各导出一份对账单。

### 2.2 区间

- **开始日期**：上次导出结束日期往前 3 天。重叠部分按平台单号自动跳过，留出重叠可以避免漏掉跨日入账的流水。
- **结束日期**：导出当天。
- 6 份报表用**同一个区间**。区间不一致时，卡余额划入可能找不到收付款余额的划出，入金可能找不到手续费。
- 第一次导入从账户开立日开始导出全部历史。

### 2.3 文件

- **保留平台给的原始文件名**，不要改名。系统靠文件名识别报表类型；卡余额流水和授权明细的文件名里带账户号，系统用它确定账户。
- **不要用 Excel 打开后另存**，不要删行、改值、调整列。另存可能把文本改成数字或日期，导致校验失败。
- 不需要合并或整理文件，导出什么就上传什么。
- 建议在共享盘按月归档原件，例如 `渠道对账/2026-10/`。系统配置了账目私有存储时，也会在导入时保存原件，可以在导入记录里下载。

## 3. 导入

1. 打开 账目管理 → **渠道** → **导入账单**。
2. 把本次导出的文件**一次全部拖入**，确认文件数量和清单一致。
3. 不确定时，可以先点“只转换，下载标准 CSV”，检查转换结果，不会入账。
4. 点 **导入并入账**。
5. 看导入结果：
   - 新增和重复行数是否合理。重复行多是正常的，因为区间有重叠。
   - 每个余额都显示 **已对平**。
6. 校验没通过时，本次**不会入账**，页面会列出文件、行号、列和原因，按第 5 节处理后重新导入。

## 4. 凭证

| 项目 | 要求 |
| --- | --- |
| 哪些流水需要 | 每笔 **入金** 至少一份；其他流水按需补充 |
| 内容 | 银行汇款回单或转账截图，能看清汇款方、金额、币种、日期和流水号 |
| 格式 | jpg、png、webp、pdf，单个不超过 20 MB，同一笔最多 20 个 |
| 怎么传 | 账户详情 → 流水 → 该笔的“上传凭证”，可直接粘贴截图（⌘V / Ctrl+V），也可拖入或选择文件 |
| 怎么查漏 | 账户详情顶部会提示“N 笔入金缺凭证”，点“只看缺凭证的入金”即可列出 |

凭证挂在平台单号上，批次撤销后重新导入，凭证仍然保留，不需要重传。

## 5. 异常处理

| 页面提示 | 原因 | 处理 |
| --- | --- | --- |
| 文件没有通过校验 | 文件被改动、报表不全或不是 SUNRATE 原始导出 | 按提示的行和列核对；重新导出原始文件后再导入 |
| 不是可识别的 SUNRATE 报表 | 文件名被改，或上传了清单外的报表 | 用原始文件名；清单外的报表不要上传 |
| 不支持的类型或描述（如退款、提现、调账） | 平台出现了系统还没有映射的流水类型 | 保留原件并通知开发补充映射；补好之前这批报表无法导入 |
| 购汇另一端缺失 | 只导了 HKD 或 USD 其中一份对账单 | 两份对账单一起导入 |
| 平台单号已导入但金额或类型不同 | 平台修改过历史流水，或文件被改动 | 先核对平台后台；确认平台数据变更时，由管理员撤销相关批次后重新导入 |
| 余额显示差额 / 不一致 | 区间没有覆盖到对账单结束日，或中间漏导了一段 | 导出覆盖完整区间的报表重新导入 |
| 流水断档 | 两次导入之间有一段时间没有导入 | 补导断档区间的报表 |
| 未配对划转 | 收付款余额对账单和卡余额流水的区间不一致，或缺其中一份 | 补导缺少的报表 |
| 出现过负余额 | 卡余额在充值前已经被扣费 | 无需处理系统数据；提醒及时给卡余额划转资金 |
| 入金缺凭证 | 还没上传凭证 | 按第 4 节上传 |
| 导错了 | 上传了错误的文件 | 管理员在账户详情的导入记录里填写原因撤销，只能从最新一批开始撤销 |

## 6. 字段注意事项

### 6.1 收付款余额对账单（PDF）

| 字段 | 用途 | 注意 |
| --- | --- | --- |
| Account ID | 渠道账户 | 必须是 `72778936`，与卡余额流水文件名中的账户号一致 |
| Currency | 余额币种 | HKD、USD 各一份，不能合在一份里 |
| Transaction ID | 平台单号，**去重依据** | 例如入金 `C26A26JRZ9`、购汇 `TXN2114914760160301057`；购汇的 HKD 卖出和 USD 买入是同一个单号 |
| Amount | 金额 | 带正负号；入金是**扣除手续费后的净额** |
| Balance | 每笔后的余额 | 系统逐行校验连续，任何一行对不上都会拒绝整批 |
| Date | 入账日期 | 只有日期没有时间；入金以这里的日期为准，不是入金记录的提交时间 |
| Description | 流水类型 | 目前支持 `Collection-Credit`、`Sell`、`Buy`、`Transfer to Card Balance` |
| Closing Balance | 期末余额 | 用来和系统余额对平 |

### 6.2 卡余额流水（CARD_BALANCES）

| 字段 | 用途 | 注意 |
| --- | --- | --- |
| Serial No. | 平台单号，**去重依据** | 不要删改 |
| Transaction Type | 流水类型 | 目前支持 `Transfer In`、`Settlement`、`Authorization Fee` |
| Transaction Amount、Balance | 金额和每笔后的余额 | 逐行校验连续 |
| Card ID | 消费所用的卡 | 结算行必有 |
| Transaction Time (GMT+8:00) | 发生时间 | 北京时间 |
| Authorization Fee | 授权手续费 | 平台按天汇总扣收，计入我方成本；拒付和 0 元验卡也会产生 |

### 6.3 授权明细（AUTHORISATIONS）

| 字段 | 用途 | 注意 |
| --- | --- | --- |
| Card Nickname | 卡所属企业 | **在 SUNRATE 后台把卡昵称设成系统中的企业名称**，一个企业一张卡。昵称为空的卡无法自动归属，新开卡时就要设好 |
| Card No. | 卡号后四位 | 用于匹配系统里登记的卡 |
| Merchant Name、Transaction ID | 商户和授权交易号 | 补充到卡消费流水 |
| Settlement Time (GMT+8:00) | 结算时间 | 用来和卡余额流水的结算行对应 |
| Status | 授权结果 | `Declined` 不入账，只用于统计拒付 |

### 6.4 入金记录（Record_Collection）

| 字段 | 用途 | 注意 |
| --- | --- | --- |
| 订单编号 | 对应对账单的 Transaction ID | 必须一致 |
| 收款金额 | 毛额 | 记入备注 |
| 手续费 | 入金手续费 | 计入我方成本 |
| 实际入账金额 | 净额 | 必须等于对账单金额，否则整批拒绝 |
| 汇款方 | 资金来源 | 目前全部是我方自有资金，不是客户付款 |
| 提交时间 | 精确时间 | 与对账单日期同一天时采用，否则以对账单日期为准 |

### 6.5 购汇记录（Record_Currency_Conversion）

| 字段 | 用途 | 注意 |
| --- | --- | --- |
| 交易编号 | 对应对账单的 Transaction ID | 必须一致 |
| 卖出金额、买入金额 | 两端金额 | 必须与两份对账单的金额一致，否则整批拒绝 |
| 汇率 | 购汇汇率 | 购汇不收手续费，成本体现在汇率中 |
| 提交时间 | 精确时间 | 用于排序 |

### 6.6 其他平台（手工整理标准模板）

按[标准账单模板](statement-template.md)整理，最容易出错的是：

- `external_id` 必须是平台给的稳定单号，同一笔流水每次导出都要相同，不能用行号或自己编的序号。
- `amount` 带正负号：进入该余额为正，离开为负，不带千分位。
- `occurred_at` 必须带时区，例如 `2026-10-22 18:16:39+08:00`。
- `balance_after` 同一余额要么全填，要么全空；填了就会逐行校验连续。
- 购汇两端的 `related_id` 填同一个交易号。
- `wallet` 用固定代码，同一个余额每次都写同一个值。

## 7. 月末核对清单

- [ ] 6 份报表区间一致，并已覆盖到上月最后一天之后
- [ ] 导入成功，每个余额都显示 **已对平**
- [ ] 没有流水断档、没有未配对划转
- [ ] 所有入金都有凭证
- [ ] 所有卡都有昵称，并能对应到企业
- [ ] 记录本月头寸和手续费成本（账户详情的“按月汇总”）
- [ ] 原始文件已按月归档
- [ ] 管理员复核完成

## 8. 接入新平台

1. 从新平台导出一个完整周期的全部报表，确认哪份报表带余额、哪份只是明细。
2. 按标准模板手工整理一次并导入，确认能对平。
3. 交给开发编写该平台的转换器，之后直接上传原始报表。
4. 在本文补充该平台的报表清单和字段说明。
