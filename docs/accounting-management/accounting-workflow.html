账目记录流程：从零开始

以 SUNRATE 发卡、为企业采购 AI 服务为例。能从平台账单拿到的，系统自动记；只有客户付款、开票、AI 厂商发票需要手工登记。

手工登记 在系统里录入 系统自动 导入或保存后自动完成 平台操作 在 SUNRATE 后台做，系统不用录 选填 留档用，不影响金额

一、三本账

收入账

客户付给公司的钱，以及我们开给客户的发票。

钱的走向：客户 → 公司银行账户

系统位置：订单里的「收款」「开票」

支出账

公司用卡给客户买 AI 服务花的钱，以及 AI 厂商开给我们的发票。

钱的走向：SUNRATE 卡 → OpenAI / Anthropic 等

系统位置：订单里的「采购（卡消费）」「AI 发票」

渠道账

公司放在 SUNRATE 里的自有资金。

钱的走向：港币入金 → 换美元 → 划转到卡余额 → 卡消费

系统位置：「渠道」页面，按平台对账单核对余额

收入账和支出账互不关联：客户付的人民币和卡上花的美元不做一一匹配，卡上也不记"余额"。卡上的钱是公司自己的，看渠道账即可。

二、一次性准备

收款账户 手工登记

登记公司收客户钱的银行账户。登记收款时选它，开票方名称也从这里带出。

厂商列表 手工登记

发卡服务商 SUNRATE；AI 厂商 OpenAI、Anthropic 等，并填别名（如 chatgpt、claude），导入时靠别名认厂商。

企业

企业管理里已有的企业直接可用。

四、导入账单时系统做了什么

需要导出的 SUNRATE 报表（同一时间区间）

  • 卡余额流水 CARD_BALANCES
  • 授权明细 AUTHORISATIONS、手续费 FEES
  • 入金记录 Record_Collection、购汇记录 Record_Currency_Conversion
  • 收付款余额对账单（港币、美元各一份 PDF）

导入后

  1. 渠道账全部入账，三个余额（港币收付款、美元收付款、美元卡余额）与平台对账单核对。
  2. 每笔卡消费按 Card ID 找到系统里的卡，进入卡所在订单；那个订单已结束时，进入该企业最近一个进行中的订单。
  3. 退款跟随原消费；授权费等手续费是公司成本，只进渠道账。
  4. 以前手工登记过的同一笔消费会自动关联，不会重复记账。
  5. 同一份报表导入两次，第二次全部跳过。

可能出现的待处理

待绑定卡账单里有张卡系统里没登记 → 去订单添加这张卡（填 Card ID），消费自动补入。
待归属订单企业没有进行中的订单 → 新建或重新打开订单，自动补入。
待复核如退款超过原消费 → 按原因处理后点「重新入账」。
待选厂商商户名认不出厂商 → 在订单里为这笔消费选厂商。

五、按月续费的订单：每月循环

③ 客户转账 → 登记收款→ ④ 开票（自动选中这笔收款）→ ⑤ 给卡上放钱→ ⑥ 用卡续费→ ⑦ 导入账单，消费自动进订单→ ⑧ 挂收款凭证（选填）→ ⑨ 登记 AI 发票 ↺ 下个月重复。订单页会提示"还有 N 笔收款没开票"或"AI 发票还没覆盖全部卡消费"。

六、每月例行检查

渠道页

  • 三个余额都显示"已对平"
  • 待处理清零
  • 入金都有凭证

订单列表

  • 有没有"还有 N 笔收款没开票"
  • 有没有"AI 发票还没覆盖全部卡消费"
  • 有没有缺凭证的收款和发票

卡片页

  • 每张卡的累计消费
  • 顶部 SUNRATE 卡余额够不够下个月用
一句话：开卡时登记 Card ID → 客户付钱登记收款、开票 → 员工用卡买服务 → 每月导入 SUNRATE 账单并处理提示 → 登记 AI 厂商的发票。能从账单拿到的，都不用手动录。
