# 企业 AI 服务：可靠性与读取优化

本次保留既有登录、会话和 direct webhook 产品合同，处理报告生成、调度、统计、导出与保留清理的 P2 项。

## 报告生成与恢复

成功分块的输出、execution 完成状态和任务 checkpoint 在同一 PostgreSQL 事务提交。任务 lease 和 revision 规则继续生效；旧 lease 不得推进新任务。

提交确认失败时，worker 不再用内存中的旧 checkpoint 覆盖数据库，也不会在当前执行中立即再次请求模型。当前执行结束后，其他 worker 通过既有 lease 到期机制重新加载已提交状态。上游已执行但本地未收到或未能持久化结果的窗口仍可能产生额外调用；这不构成跨 provider 的 exactly-once 保证。

worker 持续补位，日报与周／月报告轮换优先级。维护扫描和清理分别运行，不等待模型调用结束。

自动日报保留每日 02:00 后扫描昨天的行为，并使用持久化游标补扫最近 90 天。周报补扫最近 12 个完整周，月报补扫最近 3 个完整月；每个维护 tick、每种周期最多推进 4 个历史边界。已经存在的任务继续复用原有唯一性和幂等规则；扫描失败不越过该水位。数据缺失仍按已有报告覆盖规则表达，不伪造来源。

## 统计与明细

Web 与 BI 复用可计量请求定义和 Token 状态：

- `ready`：没有未计量请求；空范围为已知的零。
- `partial`：存在已计量和未计量请求，Token 仅包含已计量部分。
- `unavailable`：只有未计量请求，界面显示未知，CSV 对应 Token 单元格为空。

费用仍包含全部相关计费日志。SQL 在相加前提升 Token 数值类型，避免 INT 中间结果溢出。一次响应使用只读 Repeatable Read；`as_of` 仅固定时间截止点，不能阻止之后写入的迟到日志。

企业统计 API 新增：

| 参数 | 含义 |
| --- | --- |
| `section=summary` | 轻量汇总，不计算成员模型明细、趋势和排行 |
| `section=insights` | 默认；趋势、排行与首个成员模型明细页 |
| `section=member_models` | 仅获取成员模型明细及分页元数据 |
| `page`、`page_size` | 按成员分页，默认 20，最多 100；每位成员的模型组合完整返回 |
| `search`、`model`、`sort` | 仅筛选／排序成员模型明细，不改变全企业汇总 |
| `as_of` | 可复用过去 24 小时内的截止时刻 |

`member_models_page` 包含筛选后的成员数、模型组合数、不同模型数、Token 合计、计量状态及页码。模型下拉选项最多返回 500 个，其他模型仍可通过搜索定位。企业列表改为按当前页聚合人数，登录企业查询不再加载成员集合。

## CSV 导出

两个 Web 管理范围均增加 `POST .../members/usage-export`。过滤条件沿用成员列表；正文仅承载固定列顺序的本地化标题与状态标签，不改变业务字段。

成员集合、可变排序、部门／岗位、当前凭据状态与历史 Key 用量在一个数据库快照读取。服务端每批最多读取 100 名成员并写入临时文件；完整生成后再发送 CSV，快照生成上限为两分钟，失败不返回部分文件，临时文件自动清理。没有匹配成员时返回 `204`。

CSV 保留 BOM、CRLF、19 列及公式注入防护。Token 列标题明确为已计量用量；部分可计量时返回已知部分，完全无法计量时留空。导出独立于当前列表页码，页面离开、企业切换或取消会中止请求。

## 保留清理

清理使用独立的一分钟维护循环和持久化企业游标；数据库扫描租约保证多个实例不会同时推进同一游标，过期租约可以被接管。每轮最多扫描 16 家企业，每家最多连续处理 3 个有界批次。每批保留既有 100／1000 行限制，数据库锁等待上限 500ms，批次执行上限 5 秒。

单个企业失败会记录并继续处理其他企业。日志包含企业 ID、影响行数、批次数、可能积压标记与耗时。活动报告及其来源保护、企业保留周期和零值代表无限保留的规则沿用原有定义。

新增 migration `268_desktop_maintenance_progress.sql` 仅保存内部维护游标，无需人工执行数据清理或重新映射成员。
